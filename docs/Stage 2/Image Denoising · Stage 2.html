03 / Classical DIP · the prior is a line you write yourself

Total variation, as actually implemented

while i < max_num_iter:          # default 200 — per image
    d   = -p.sum(0)              # divergence of the dual field
    out = image + d
    E   = (d**2).sum()            # fidelity term
    E  += weight * norm.sum()   # ← the prior. Hand-written.
    p  -= tau * g
    p  /= norm
scikit-image 0.26.0 · skimage/restoration/_denoise.py line 405 — Rudin–Osher–Fatemi
No training

No dataset, no optimiser, no weights. The algorithm is the model.

One knob, set by a human

weight trades smoothing against fidelity. You tune it — per image, per noise level.

Nothing is reused

200 iterations run again, from scratch, for the next image. Forever.

04 / Why the field left this behind

Two costs, both visible from the code

Cost 1 — test time is compute time

Every image restarts an optimisation. Reported at 512×512 in the DnCNN paper, Table IV:

BM3D2.85 s
WNNM773 s
DnCNN-B, GPU0.060 s
Cost 2 — there is no artefact

A decade of BM3D research produced no downloadable object. You cannot install a tuned prior, fine-tune it, or hand it to a colleague.

The deep era's real contribution to engineering is not accuracy. It is that the prior became a file.

05 / 2017 · DnCNN — the loop becomes a list comprehension

Same shape, different substance

m_head = B.conv(in_nc, nc, mode='C'+act_mode[-1])
m_body = [B.conv(nc, nc, mode='C'+act_mode) for _ in range(nb-2)]
m_tail = B.conv(nc, out_nc, mode='C')
self.model = B.sequential(m_head, *m_body, m_tail)

def forward(self, x):
    n = self.model(x)
    return x - n          # predict the noise, then subtract it
cszn/KAIR · models/network_dncnn.py line 20 · nb=17..20, nc=64, mode 'BR' = BatchNorm + ReLU

The classical while loop iterated in time. DnCNN unrolls the same idea in depth — 20 stacked layers, run once.

return x - n is residual learning: the paper's central trick, in one line. The prior is now the 0.67 M numbers inside self.model.

06 / 2017 · where the training pairs come from

The noise is manufactured, on the fly, per sample

patch_H = img_H[rnd_h:rnd_h+ps, rnd_w:rnd_w+ps, :]      # random crop
patch_H = util.augment_img(patch_H, mode=random.randint(0,7))  # flip / rot

img_L.add_(noise)
cszn/KAIR · data/dataset_dncnn.py · __getitem__
What this buys

Infinite training pairs from a folder of clean photographs. No paired capture rig, no registration. It is why deep denoising took off before deep deblurring did.

What it costs — remember this line

img_H must exist. The whole pipeline rests on owning a clean image. That assumption is the next bottleneck, and it sits right here in __getitem__.

07 / The fork

By 2018 the code showed two limits, and two communities went after them separately

Limit in dataset_dncnn.py

img_H — you need clean data.

The data branch. Changes the supervision — what goes in, what it is scored against.
→ Noise2Noise · Noise2Void · ZS-N2N · P2N

Limit in network_dncnn.py

B.conv(nc, nc) — a 3×3 kernel sees 3×3 pixels.

The architecture branch. Changes the operator — what computes in between.
→ Restormer · NAFNet · SCUNet · MambaIR

Both branches are alive in 2026. Neither has absorbed the other.

08 / Data branch, 2018 · Noise2Noise

The entire paper is one if statement

if noise2noise:
    meansq_error = tf.reduce_mean(tf.square(noisy_target - denoised))
else:
    meansq_error = tf.reduce_mean(tf.square(clean_target - denoised))
NVlabs/noise2noise · train.py line 105 · commit 7355519

Same network, same optimiser, same loader. The target swaps from a clean image to a second noisy photograph of the same scene — and it still converges, because the noise has zero mean and an L2 loss regresses to the mean.

An engineering detail worth noticing: this repo is import tensorflow as tf, pinned to scipy==1.1.0, Pillow==5.2.0. It is the last major denoiser in our study that is not PyTorch. In everything that follows, the framework question has exactly one answer.

A CVPR 2025 paper ships the 2018 Noise2Noise U-Net unchanged. The class name is not a coincidence — it is a citation.

So the data branch never was an architecture story. Everything that changed between 2018 and 2025 lives in one function — noise_estimation_loss — and that function does more than score outputs: it builds the inputs too. Only opening both files shows it.

10 / Data branch, 2025 · what did change

P2N: renoise the estimate, then demand agreement

output = self.model(noisy)
noise  = noisy - output                             # estimated noise

output_p = self.model(output + noise   * sigma_p)   # y⁺ = x̂ + α·n̂
noise_n  = self.noise_generate(noise)              # return noise * (-1)
output_n = self.model(output + noise_n * sigma_n)   # y⁻ = x̂ − α·n̂

return self.criterion(output_p, output_n)          # make them agree
Li-Tong-621/P2N-plus · test.py line 121, branch 'RDC+DSC' — commented “CVPR version”

Positive to negative is literally noise * (-1) — one line, at test.py:109. The paper names the two halves: building y⁺ and y⁻ is renoised data construction (RDC); training them to agree is denoised consistency supervision (DCS). Those are the abbreviations on the next slide.

Noise2Void must mask pixels; ZS-N2N must downsample. Both discard information. Renoising keeps every pixel — that is the “information-lossy barrier” of the title.

11 / Data branch · closing

The network never moved. The target did.

Every advance on this branch is a different answer to one question: if you have no clean image, what do you train against?

2018 · Noise2Noise

A second noisy shot of the same scene.
Cost: you need two.

2019 · Noise2Void

The pixel it was not allowed to see.
Cost: pixels thrown away.

2023 · ZS-N2N

The other half of a downsampled pair.
Cost: half the resolution.

2025 · P2N

Its own output, renoised the other way.
Cost: none — every pixel kept.

Four papers, one network. UNet_n2n_un — 48, 96, 64, 32 — unchanged since 2018.

The other branch made the opposite bet: keep the supervision, rebuild the network. That is slides 12 to 14.

12 / Architecture branch, 2022 · Restormer

Attention, transposed so that it scales

q = rearrange(q, 'b (head c) h w -> b head c (h w)', head=num_heads)
k = rearrange(k, 'b (head c) h w -> b head c (h w)', head=num_heads)

attn = (q @ k.transpose(-2, -1)) * self.temperature
attn = attn.softmax(dim=-1)
swz30/Restormer · basicsr/models/archs/restormer_arch.py line 111

Channels go second-to-last, pixels go last. So the product is C/k × C/k — a channel covariance — not HW × HW. Cost falls from O(H²W²C) to O(HWC²/k): linear in pixels.

This is the direct answer to DnCNN's 3×3 limit. A pixel can now influence any other pixel, at a price you can afford on a full-resolution photograph.

13 / Architecture branch, 2022 · NAFNet

The rebuttal: delete the activation function

class SimpleGate(nn.Module):
    def forward(self, x):
        x1, x2 = x.chunk(2, dim=1)
        return x1 * x2
megvii-research/NAFNet · NAFNet_arch.py line 22 — that is the entire class

Wherever a network would apply ReLU, GELU or Softmax, NAFNet splits the tensor and multiplies the halves. Its claim: the gains credited to attention were mostly gains from gating.

Every block starts as the identity

beta and gamma initialise to zero, so a 36-block network begins life as a plain U-Net skip path and switches depth on by gradient descent. Hence warmup_iter: -1 in the config.

A loss that is the metric

PSNRLoss = (10/ln10)·mean(log(MSE per image)) — literally −PSNR. The log sits inside the batch mean, so easy images stop dominating the gradient. Not perceptual, not adversarial: metric-aligned.

14 / Architecture branch, 2023–24 · two more answers

SCUNet refuses to choose. MambaIR changes the mathematics.

SCUNet · split the channels
conv_x, trans_x = torch.split(...)
conv_x  = conv_block(conv_x) + conv_x
trans_x = trans_block(trans_x)   # Swin
x = x + conv1_2(cat(conv_x, trans_x))

Half the channels take a 3×3 conv for texture, half take windowed attention for structure. Its real edge is elsewhere: a randomised degradation pipeline — blur, Poisson, JPEG, ISP — which is why its blind weights survive real photographs.

MambaIR · scan instead of attend
A_log_init(d_state, d_inner,
           copies=4, merge=True)
# an image has no scan order,
# so scan four ways and merge

A selective state-space recurrence with input-dependent A, B, C. Linear cost and global context — but paid for in a different currency, as the next slide shows.

15 / Engineering reality

What a modern denoising repository actually is

Not a library — a fork of a training harness

Restormer, NAFNet and MambaIR each vendor a modified copy of BasicSR into a local basicsr/. Importing one architecture file runs the whole package __init__ chain: NAFNet_arch pulled in lmdb, which the forward pass never touches. Two of these repos cannot coexist in one Python process — they collide on the basicsr namespace.

And one of them will not run at all

MambaIR line 11 is an unconditional from mamba_ssm … import — no try/except, no CPU fallback. ModuleNotFoundError. Pinned to CUDA 11.7 / PyTorch 2.0.1.

The model is now a YAML entry
network_g:
  type: NAFNet
  width: 64
  enc_blk_nums: [2,2,4,8]
  middle_blk_num: 12
datasets:
  type: PairedImageDataset
  io_backend: {type: lmdb}

In 2017 the model was DnCNN(nc=64, nb=20) in a script. Today architecture, data, optimiser, loss and metrics are one declarative file resolved through a registry — so a reproduction attempt is a diff between two YAMLs.

Parameters do not predict speed

NAFNet carries 4.4× Restormer's parameters and runs 5.5× faster. 1×1 and depth-wise convs hit fast kernels; rearrange forces layout changes.

And a parameter table can mislead

Turning SPI on cuts parameters 6.7% and raises latency 2.5× — every layer runs twice, on x and −x. MambaIR's own changelog admits its published thop figures were wrong and are larger under fvcore.

The prior moved out of the algorithm into the weights — then, in the self-supervised branch, back out of the weights into a per-image optimisation that needs no clean data at all.

Which one to deploy depends on the constraint: NAFNet on a GPU with paired data, SCUNet when memory is tight, P2N when no clean image exists. The fork has not closed — and the code shows why.
